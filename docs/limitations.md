# 当前边界与后续方向

本次整理以配置分离、目录规范化和文档补充为主，保留原有业务处理流程。编译通过不等于已重新完成硬件和云端验证。

## 已明确的功能边界

- 光敏数据是相对百分比，没有 lux 标定。
- 风扇是三档 PWM 开环调速，没有转速传感器反馈。
- 报警开关控制“使能”，蜂鸣器还受本地环境阈值约束。
- 小程序以5秒轮询显示云端最新值，不是推送式实时刷新。
- OLED驱动保留，当前主循环没有刷新环境数据。
- 固件使用普通TCP连接，不包含TLS、OTA或RTOS。

## 待改进事项

1. **接收缓冲与报文边界**：当前根据接收计数暂时不变判断完成；需要完善IPD长度、TCP字节累计和MQTT Remaining Length解析，避免半包、多包及解析时覆盖。
2. **HAL串口接收**：HAL已经把字节写入接收缓冲，现有回调又读取DR；应整理为明确的字节接收和环形缓冲所有权。
3. **采集周期与有效性**：DHT11目前每轮主循环调用，需按模块手册采样并处理失败、过期和数据有效标志。
4. **JSON和范围校验**：补充根节点 / params检查、L/B类型校验、F=0—3范围校验和非法指令处理。
5. **设备在线维护**：完善Wi-Fi / TCP / MQTT分层故障恢复、超时与重新订阅。
6. **控制结果闭环**：补充物模型属性设置回复、执行器实际控制状态上报，以及小程序等待 / 失败 / 确认状态。
7. **小程序数据映射**：按属性标识替代数组固定下标；保存和清理轮询定时器，检查业务响应并处理过期值。
8. **内存与库边界**：审计旧MQTT/cJSON的有界解析、分配失败和释放路径；根据峰值评估512字节堆与1KB栈配置。

这些是后续工作方向，没有在本次仓库整理中全部修复，也没有给出未经测量的性能或可靠性指标。
